## (a) What the owner asked for and decided about splash / first launch / auth

### Takeaway
The owner's vision is a **play-first, interactive first launch led by the Wael character**: welcome by Wael, pick level (1ère to Bac), pick favourite subject, play a 3-screen quiz on real Tunisian programme content, and only then authenticate to play again. The owner wants it to feel like an **experience, not a sequence of screens**, and the account to feel encouraged, not forced. Decisions recorded: "plays before it asks", no fake loading bar, level and section in one step, questions in the language the lycée teaches in, no timer or game over, sign-up = name + phone + SMS code + password (+ parent's number under 18).

## (b) How the game app's splash / first launch / auth screens are built today

### Takeaway
`/mobilegame` is a **landscape-first** React app rendered inside a true-size iPhone 13 Pro Max (926 × 428 pt) or Galaxy A55 (832 × 384 dp) frame on desktop, or full-screen on a real phone, with safe areas exposed as `--gs-top/left/right/bottom`. Only the **splash** uses the new 3D art (floating island + 3D Wael waving); **every other screen still uses the flat 2D `Caracter.png`** (a 185 × 328 px cartoon, arms crossed) on a dark teal "chapter" panel, and the login also uses the flat SVG `TownArt`. Screens are a two-column split: content on the start side (right in RTL), Wael panel on the end side.

## (c) Design-system rules any 3D character or 3D effect must respect

### Takeaway
Four skills stack: `wael-design-system-soft` (brand), `wael-gamified` (the `play` content look: lips, one lime moment, one burst, sound on the same frame, strict reduced-motion), and `wael-mobile-ios` / `wael-mobile-android` (chrome, insets, motion timing, landscape rules). Several `play` rules directly constrain 3D work: **depth only on pressables**, **no blurred shadows on UI**, **nothing animates on mount except a 240 ms stagger**, **nothing loops**, **one celebration per visit**, **"no neutral Wael / Wael never speaks"**. The game apps have already been granted exceptions (points/levels; Wael with a speech bubble in practice), but the skill text has not been amended — any 3D idle loop, entrance, or talking Wael needs an explicit amendment.

### Cited Findings
**Palette and type (tokens, `src/styles/v2.css`):**
- Light: `--v2-ink #172e5b` (navy), `--v2-brand #0491a5` (teal), `--v2-deep #08434b`, `--v2-cta #8aff6b` (lime), `--v2-on-cta #172e5b`, `--v2-live #ff3b3e`, `--v2-done #f28b14` (orange), `--v2-brand-text #036b7a`, `--v2-grad` teal → lime 135°, `--v2-chapter` `linear-gradient(150deg, #0a7d8e, #08434b 62%, #062f36)`. Dark values exist for each (e.g. surface `#111d38`, canvas `#0a1428`) — [v2.css](file:///C:/Projects/Wael%20Academy%20Prototype/src/styles/v2.css)
- Derived "edge" tokens for lips: `--v2-edge-cta #5bcd3f`, `--v2-edge-brand #036b7a`, `--v2-edge-deep #052a30`, `--v2-edge-live #c92c2f`, `--v2-edge-done #b9680b`, `--v2-edge-tile rgb(23 46 91/.14)`; "No new hue. A new colour is a derived edge of an existing one" — [wael-gamified SKILL.md](file:///C:/Projects/Wael%20Academy%20Prototype/.claude/skills/wael-gamified/SKILL.md)
- Font: Cairo is the student-space/game family ("Cairo, display AND interface", variable 200–1000, Arabic + Latin) — [fonts.css](file:///C:/Projects/Wael%20Academy%20Prototype/src/styles/fonts.css). Skill: Cairo only, weights 400–700 for body on iOS, never light, `letter-spacing: 0`; panel titles 800, CTA 800, counters 900 tabular, never 1000, never letter-spaced Arabic — [wael-mobile-ios SKILL.md](file:///C:/Projects/Wael%20Academy%20Prototype/.claude/skills/wael-mobile-ios/SKILL.md); [wael-gamified SKILL.md](file:///C:/Projects/Wael%20Academy%20Prototype/.claude/skills/wael-gamified/SKILL.md)

### Inferences
- Any 3D approach must run in WebKit (iOS Safari / WKWebView) and on a Galaxy A55-class GPU inside a webview, in landscape, with reduced-motion and reduced-transparency fallbacks, and lazy-loaded per route so the splash stays instant ("a door, not a wait").
- Given the project's precedent (CSS over libraries, the guide's pre-rendered sprite workflow, "no fake loading"), pre-rendered 3D (layered PNG/WebP, sprite sheets, short alpha video) is the path of least friction; a real-time 3D runtime would be a deliberate new dependency needing a decision and a performance check.
- Note: the onboarding store uses zustand although CLAUDE.md lists it among redundant libraries; it is already installed, so the "minimal stack" rule is applied pragmatically in this codebase.

### Gaps
- No performance measurements of the current splash assets on real devices were found locally.
- No decision record exists yet on Rive, Lottie, three.js/R3F or video-with-alpha for the game apps.
